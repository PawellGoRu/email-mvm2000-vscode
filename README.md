# Письма PowerHV — руководство

_Обновлено: 22 октября 2026 года._

## Быстрый старт

Из корня проекта выполните:

```sh
npm run build       # обычное письмо: dist/powerhv-introduction.eml
npm run campaign    # персональные письма из recipients.csv: dist/campaign/
npm run mail-template # HTML для предпросмотра в браузере
npm test            # автоматические проверки
```

Генераторы создают файлы, но **не отправляют письма**. Для реальной отправки откройте EML в почтовом клиенте или используйте свой сервис рассылок.

## Файлы проекта

- `src/email.html` — основной шаблон обычного письма.
- `src/email-responsive.html` — адаптивный шаблон кампаний и HTML-предпросмотра.
- `scripts/build-eml.mjs` — сборка обычного EML.
- `scripts/send-campaign.mjs` — персонализация и сборка EML из CSV.
- `scripts/build-mail-template.mjs` — создание `preview/mail-template.html`.
- `scripts/build-mail-template.applescript` — открытие готового EML в Apple Mail на macOS.
- `test/` — автоматические тесты.

## Редактирование шаблонов

Изменяйте нужный HTML-файл. Если текст должен совпадать в обычном письме и кампании, внесите правки в оба шаблона. Откройте HTML в браузере для предварительной проверки; окончательное отображение проверяйте в почтовых клиентах.

Оба шаблона содержат встроенный баннер. Сборщик обычного EML переносит его в отдельную inline MIME-часть и связывает с HTML через `cid:powerhv-banner`.

## Обычное письмо

```sh
npm run build
```

Результат: `dist/powerhv-introduction.eml`. Можно указать другой путь напрямую:

```sh
node scripts/build-eml.mjs /путь/к/письму.eml
```

В EML поле `To` оставлено пустым. Перед отправкой выберите отправителя, укажите получателя и проверьте тему и заголовок отписки. Шаблон автономен: баннер находится внутри письма, внешний URL для изображения не нужен.

## Персональная кампания

CSV должен содержать заголовки `email`, `firstName`, `lastName` и не менее одной записи. Пример:

```csv
email,firstName,lastName
anna@example.com,Анна,Иванова
"pavel@example.com","Павел, Петрович",Петров
```

Запустите кампанию из корня проекта:

```sh
npm run campaign
```

Скрипт читает `recipients.csv` и записывает EML в `dist/campaign/`. Для других файлов и папок используйте:

```sh
node scripts/send-campaign.mjs /путь/к/получателям.csv /путь/к/выходной-папке
```

Парсер понимает кавычки, экранированные кавычки и переносы строк внутри quoted-полей. Некорректные кавычки, адреса и повторяющиеся адреса отклоняются. Значения имён экранируются перед вставкой в HTML. Для каждого адреса создаётся отдельное письмо с уникальным именем файла.

Выходная папка управляется генератором: старые EML, созданные им, удаляются при повторной сборке. При первом запуске распознаются старые имена формата `slug-email-domain.eml`; не храните такие ручные файлы в папке кампании. Для последующих запусков список файлов генератора хранится в `.campaign-manifest.json`.

Проверьте отправителя и URL отписки в `scripts/send-campaign.mjs` перед реальной рассылкой. Настройки SPF, DKIM и DMARC выполняются отдельно на стороне домена и почтового сервиса.

## Шаблон в Apple Mail (macOS)

### Рекомендуемый способ: открыть EML

1. Соберите письмо: `npm run build`.
2. Откройте `dist/powerhv-introduction.eml` двойным щелчком или выполните `open dist/powerhv-introduction.eml`.
3. В Mail нажмите «Переслать», укажите получателя и выберите нужный аккаунт отправителя. Перед отправкой проверьте тему и содержимое.
4. Чтобы сохранить заготовку, выберите «Файл → Сохранить как шаблон».

Для шага 2 можно использовать AppleScript-помощник:

```sh
osascript scripts/build-mail-template.applescript "$(pwd)/dist/powerhv-introduction.eml"
```

### Альтернатива: скопировать HTML из браузера

1. Выполните `npm run mail-template`.
2. Откройте `preview/mail-template.html` в Safari, скопируйте отрисованное письмо и вставьте его в новое сообщение Mail.
3. Проверьте текст, баннер и подпись. В шаблоне останутся персональные плейсхолдеры — замените их перед отправкой.
4. Сохраните сообщение через «Файл → Сохранить как шаблон».

AppleScript-помощник принимает путь к EML; для HTML используйте Safari и копирование содержимого. В обоих вариантах проверьте результат в самом Mail перед отправкой.

## Проверки перед отправкой

- Запустите `npm test`, чтобы проверить сборку EML, MIME-части, шаблоны и обработку CSV.
- Откройте итоговый EML в целевом почтовом клиенте и проверьте отображение текста, баннера и подписи.
- Перед рассылкой проверьте адрес отправителя, получателей, тему и ссылку отписки.
- Для массовой отправки настройте доменную аутентификацию (SPF, DKIM, DMARC) и отправляйте письма через почтовый сервис. Этот проект только генерирует файлы и не проверяет доставляемость.
